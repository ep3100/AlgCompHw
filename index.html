Automating Composition with Pitch Set Theory and Web Audio

Lab 5 — Automated Composition

What Is Pitch Set Theory?

Pitch set theory represents notes not as letter names but as integers 0 through 11, where 0 is C, 1 is C#, and so on. A chord or motif becomes a set of these integers — for example, a minor triad rooted on C is {0, 3, 7}. The power of this representation is that tranformations can be expressed mathematically. There are three core operations: transposition shifts every pitch class by n semitones (mod 12), inversion reflects each pitch class around an axis, and retrograde simply reverses the order of notes in the set. This tool creates an automated process for These ideas; given a pitch class set, it randomly chains those events together to produce a sequence of set which are then played.

Building It

The core operations themselves were pretty interesting to implment. Transposition is one line of code — map each pitch class to (pc + n) % 12. Inversion is (axis - pc) % 12. Retrograde is just array reversal. What surprised me was how much musical character comes from decisions that have nothing to do with the theory itself, but how you chain the operations together and how you weight the probability of each one occurring.

For example, choosing a base octave dramatically changes the feel of the output. The same sequence of pitch classes sounds deep in octave 3 and a bit brighter in octave 5. Similarly, tuning the operation weights — making transposition twice as likely as inversion, say — shapes whether the output drifts gradually through pitch space or jumps around erratically.

On the Web Audio side, each note is synthesized with an OscillatorNode routed through a GainNode with an exponential decay envelope. This is bare-minimum synthesis, but it's enough to hear the relationships between pitch classes clearly. I also built a small piano roll visualization using a canvas element, which color-codes notes by which operation produced them. You can visually spot when a retrograde mirrors a previous pattern, or when a transposition shifts the whole set up by a consistent interval.

Reflections

The biggest insight from this project is that pitch set theory works better as a generative tool than I expected. In class, it was mostly presented as mostly math and backend stuff, rather than actual sounds. It was interesting to see how these transformations actually change the musicality of whatever is being played; b minor triad transposed is still a minor triad. Inverted, it becomes a major triad, as an example.

More importantly, the output is clearly not "composed" in a traditional. There's no sense of phrasing, tension, or resolution. The randomness of operation selection means there's no large-scale form. This is where a human composer would step in and create some sort of rules to mimic a certain genre or style of a piece/music. I think that's the honest takeaway about algorithmic composition in general: the algorithm gives you material, but the musicality still has to come from somewhere.
